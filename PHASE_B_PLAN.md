## 1. СОГЛАСОВАННЫЕ РЕШЕНИЯ

| # | Решение | Детали |
|---|---------|--------|
| 1 | **Градация 0-3** | 0=молчу, 1=реакция/гифка/стикер, 2=обычный текст, 3=развёрнутый (нужна память) |
| 2 | **Единый вызов классификации** | «отвечать? + нужна ли память + какой query» — в одном вызове DeepSeek (fast) |
| 3 | **Fast-модель для классификации** | `deepseek-chat` (НЕ reasoner/thinking) — мгновенно |
| 4 | **Reply-to-message** | Обрабатываем и в insert (контекст), и в логике ответа (сигнал «обращаются ко мне») |
| 5 | **Группировка по времени** | Чат отправляется в LightRAG блоками 10-15 мин, не поштучно |
| 6 | **LightRAG = «база фактов»** | Достаём без генерации (`only_need_context=true`), «думает» только DeepSeek бота |
| 7 | **Промпт** | Указать, что факты о людях есть в LightRAG (не дублируем имена) |
| 8 | **Частота индексации** | Ночью (можно реже — раз в N дней) + периодическая чистка raw text |
| 9 | **Имена в промпт** | ❌ Не дублируем (бот видит их в контексте) |

## 4. НОВЫЙ ПАЙПЛАЙН ОТВЕТА (детально)

### 4.1. ConversationAnalyzer (НОВЫЙ, fast)

**Цель:** один вызов DeepSeek вместо двух, мгновенно.

**Промпт классификатора (структурированный вывод):**
```
Ты — анализатор группового чата. Оцени сообщение и верни JSON.

Контекст (последние сообщения):
{context_with_authors_and_reply}

Текущее сообщение от {author}:
{message}

reply на: {reply_to_text or "нет"}

Верни СТРОГО JSON:
{
  "grade": 0-3,
    // 0 = не отвечать (флуд, не к боту, неинтересно)
    // 1 = короткая реакция (стикер/гифка/смайл/короткое слово)
    // 2 = обычный содержательный ответ
    // 3 = развёрнутый ответ, требует вникания/памяти
  "needs_memory": true/false,
    // true если есть упоминание прошлого, конкретного человека,
    //    фактов, истории, или grade==3
  "rag_query": "поисковый запрос для базы знаний" or null,
    // если needs_memory — конкретный запрос (например "Максим Dota игры")
    // если нет — null
  "reason": "кратко почему"
}
```

**Реализация:** fast `deepseek-chat`, низкая температура (0.3), `response_format=json` (DeepSeek поддерживает structured output). Парсим JSON, на сбой → fallback на эвристики.

### 4.2. Градация → формат ответа

| grade | Что делает бот |
|-------|---------------|
| 0 | Молчит |
| 1 | Стремится к реакции: промпт просит «коротко: стикер/гифка/смайл/1-3 слова» |
| 2 | Обычный ответ (как сейчас) |
| 3 | Развёрнутый, max_tokens больше, акцент на использование фактов из LightRAG |

Это решает боль №2 (баланс стикеров/гифок): бот **понимает контекст**, а не случайно шлёт гифку.

### 4.3. RagClient.retrieve()

```python
# Псевдокод (не финальный)
POST {LIGHTRAG_URL}/query
{
  "query": rag_query,
  "mode": "mix",              # согласовано: mix дал лучший результат
  "only_need_context": true,  # КЛЮЧ: без генерации, только факты
  "top_k": 5                  # компактно
}
→ возвращает текст фактов (без «думанья» LightRAG)
```

**Обработка:** таймаут 5 сек, при ошибке → отвечаем без фактов (бот не должен падать).

### 4.4. Вставка фактов в промпт (brain.py)

```
[системный промпт персоны]

📊 ИЗВЕСТНЫЕ ФАКТЫ (из базы знаний, используй если релевантно):
{rag_facts or "нет релевантных фактов"}

💬 ПОСЛЕДНИЕ СООБЩЕНИЯ:
{context}

📨 ТЕКУЩЕЕ:
{message}
```

## 5. НОЧНОЙ ПАЙПЛАЙН (детально)

### 5.1. RagIngestor (НОВЫЙ)

**Шаг 1 — Сбор данных за период:**
- Источник: Firebase (надёжно) с fallback на `daily_log`
- Период: настраиваемый (`RAG_INGEST_PERIOD_HOURS=24` или дней)
- Берём все сообщения за период

**Шаг 2 — Группировка по времени (КЛЮЧЕВОЕ):**
```
Алгоритм:
  сортируем сообщения по времени
  проходим по ним, группируя в блоки:
    если gap между сообщениями > 15 МИН → новый блок
    ИЛИ блок > 30 сообщений → новый блок
  для каждого сообщения:
    если есть reply_to_message → добавляем его текст в начало (как контекст)
  
Результат: список текстовых блоков типа:
  "[14:30-14:42] Вася: я люблю киев\nПетя (reply на Васю): согласен\nМаксим: +"
```

**Это решает проблему «я люблю киев + хахаха»** — согласие попадает в тот же чанк, DeepSeek extraction видит связь.

**Шаг 3 — Отправка в LightRAG:**
```python
POST {LIGHTRAG_URL}/documents
{
  "text": block_text,   # по одному блоку за раз
  ...
}
```
LightRAG сам сделает extraction (DeepSeek) + embeddings (OpenAI).

**Шаг 4 — Отчёт + опц. чистка:**
- Отчёт в чат: «Проиндексировано N сообщений за день»
- Опц.: раз в неделю `DELETE` старых документов из raw text (граф оставляем)

### 5.2. Частота

- **Базово:** каждую ночь (как сейчас анализатор), `run_hour` из `.env` (починим баг №2)
- **Опция в конфиге:** `RAG_INGEST_EVERY_N_DAYS=1` (можешь поставить 3-7)
- Планировщик считает дни от последнего успешного ingest

### 5.3. Идемпотентность (защита от рестартов)

- Перед ingest: записать в Firebase `rag_last_ingest_timestamp`
- После успеха: обновить
- При рестарте: продолжить с последней точки (не вставлять дубль)
- Документы помечаем идентификатором периода (для чистки)
